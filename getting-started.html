このページで用意するもの

共通：VS Code、Git、Quarto CLI、uv。AI：CodexまたはClaude CodeのVS Code拡張を、どちらか1つ。

AI拡張は、利用できるアカウントでサインインします。公開リポジトリのcloneは、GitHubアカウントなしでも行えます。自分のリポジトリに保存・公開するときにGitHubへのサインインが必要です。

このガイドはWindowsとmacOS向けです。サンプルのビルド検証環境はmacOSです。

番号順に開いて進めてください
01VS Codeをインストールするスライドの文章と図を編集する場所を用意します。共通

VS Code（Visual Studio Code）は、ファイル編集とAIへの依頼、コマンドの実行を1つの画面で行うアプリです。

VS Codeのダウンロードページ ↗

Windows

  1. ダウンロードページでWindows用のインストーラーを選びます。
  2. ダウンロードしたファイルを実行し、案内に沿ってインストールします。
  3. インストール後、スタートメニューから「Visual Studio Code」を開きます。

Windowsの公式手順 ↗

macOS

  1. Mac用のファイルをダウンロードします。Apple Silicon／Intelは使用するMacに合わせて選びます。
  2. ダウンロードしたDMGを開き、「Visual Studio Code.app」を「アプリケーション」へ移動します。ZIPの場合は展開してから移動します。
  3. アプリケーションからVS Codeを開きます。

macOSの公式手順 ↗

最初に覚える3つの場所

エクスプローラー
左側のファイル一覧です。ここからメモやスライドを開きます。
拡張機能
左側の四角が並んだアイコンです。QuartoやAIの機能を追加します。
ターミナル
上部メニューの「ターミナル → 新しいターミナル」で開きます。下部に現れる入力欄へコマンドを貼り付けてEnterで実行します。
日本語表示にしたいとき

拡張機能で「Japanese Language Pack」を検索し、発行元がMicrosoftのものをインストールします。案内が表示されたらVS Codeを再起動してください。英語表示のままでも作業できます。

ここまでの確認：VS Codeが開き、「ターミナル → 新しいターミナル」を選べればOKです。

02Gitをインストールするテンプレートをダウンロードし、変更を記録する道具です。共通

VS CodeにGitの操作画面は含まれますが、Git本体も必要です。まずVS Codeのターミナルで確認します。

git --version

バージョン番号が出れば、インストール済みです。下の導入手順を飛ばして次へ進みます。

Windows

  1. Git公式のWindows用ページから、PCに合うGit for Windowsをダウンロードします。
  2. インストーラーを起動します。通常は標準設定で進められます。既定のエディタを選ぶ画面では、VS Codeを選ぶと後で扱いやすくなります。
  3. 完了したら、VS Codeをすべて閉じて開き直します。

このガイドのコマンドはPowerShellで実行できます。Git for Windowsに付属するGit Bashは、Claude CodeのWindows環境でも利用されます。

macOS

Gitがなければ、ターミナルで次を実行し、表示された画面でCommand Line Toolsをインストールします。

xcode-select --install

完了まで待ち、VS Codeのターミナルを開き直します。Homebrewを導入済みなら、brew install gitも選べます。

macOSのGit公式手順 ↗

ここまでの確認：git --versionでgit version …と表示されればOKです。

03Quarto本体と拡張機能を入れるQMDの文章をHTMLへ変換できるようにします。共通

Quarto CLIは変換する本体、VS Code拡張は編集の補助です。まず本体をインストールします。

Quartoの公式ダウンロードページ ↗

Windows

  1. 公式ページでWindows用のインストーラー（.msi）を選びます。
  2. ダウンロードしたファイルを開き、案内に沿ってインストールします。
  3. VS Codeを再起動し、新しいターミナルを開きます。

macOS

  1. 公式ページでmacOS用のインストーラー（.pkg）を選びます。
  2. ファイルを開き、案内に沿ってインストールします。
  3. VS Codeを再起動し、新しいターミナルを開きます。

Quarto拡張も追加する

  1. VS Codeの「拡張機能」を開き、「Quarto」を検索します。
  2. Quarto拡張をインストールします。
  3. 後で.qmdを開くと、文章や設定の編集を補助してくれます。

このリポジトリの配布用HTML/PDFは、後の手順にあるscripts/slides.py buildで生成します。

quarto --version

ここまでの確認：ターミナルにQuartoのバージョン番号が出れば、本体を使用できます。

Quarto公式：VS Codeでの利用 ↗

04Codex または Claude Codeを入れるどちらか1つの拡張を選び、サインインします。選択

どちらも、VS Codeで開いたプロジェクトのファイルを読み、文章やHTML図の作成を手伝います。自分が利用できるサービスを1つ選んでください。

Codexを使うOpenAIのVS Code拡張
  1. VS Codeの「拡張機能」を開き、Codexを検索します。
  2. 発行元がOpenAIの拡張を選び、インストールします。拡張のページ ↗
  3. Codexのアイコンをクリックしてパネルを開きます。見つからない場合は、コマンドパレットでCodex: Open Codex Sidebarを実行します。
  4. Sign in with ChatGPTを選び、ブラウザでサインインしてVS Codeに戻ります。
  5. 後の手順でquarto-htmlフォルダを開いたら、Codexのチャットから依頼します。

コマンドパレットはWindowsでCtrl＋Shift＋P、macOSで⌘＋Shift＋Pです。

利用可否・上限はアカウントや組織の設定によります。APIキーで利用する場合はAPI利用分が別途課金されるため、まず利用可能なChatGPTアカウントでのサインインを確認してください。

公式：Codex IDE拡張 · サインイン方法

Claude Codeを使うAnthropicのVS Code拡張
  1. VS Codeの「拡張機能」を開き、Claude Codeを検索します。
  2. 発行元がAnthropicの拡張をインストールします。拡張のページ ↗
  3. Claude Codeのアイコンをクリックします。見つからない場合はコマンドパレットでClaude Codeを検索し、Open in New Tabなどを選びます。
  4. Sign inを選び、ブラウザで認証してVS Codeへ戻ります。
  5. 利用できるClaudeの有料プラン、またはClaude Consoleのアカウントでサインインします。拡張のチャットにはCLIが同梱されるため、ターミナル用CLIを別に入れる必要はありません。

ターミナルでclaudeコマンドも使いたい場合は、別途CLIを導入します。このガイドでは拡張のチャットを使います。

公式：VS Code拡張 · Windowsなどの環境設定

ここまでの確認：選んだAI拡張でサインインでき、チャット入力欄が表示されればOKです。

05テンプレートリポジトリをcloneするmurata-lab/quarto-htmlを、自分のPCにコピーします。共通

cloneは、GitHub上のリポジトリを履歴ごと手元にコピーする操作です。ローカルで編集しただけでは、研究室のリポジトリは変更されません。

テンプレート：murata-lab/quarto-html ↗

方法A：VS Codeの画面からcloneする

  1. コマンドパレットを開き、Git: Cloneを検索して実行します。
  2. 次のURLを入力してEnterを押します。
https://github.com/murata-lab/quarto-html.git
  1. 保存先の親フォルダを選びます。たとえば「ドキュメント」の下の作業用フォルダです。
  2. cloneが終わったらOpen／開くを選びます。
  3. 左のファイル一覧でREADME.md、decks、scriptsが見えることを確認します。
方法B：ターミナルでcloneする

保存先の親フォルダをVS Codeで開いてから、ターミナルで実行します。

git clone https://github.com/murata-lab/quarto-html.git
cd quarto-html

その後「ファイル → フォルダーを開く」で、できたquarto-htmlを開きます。codeコマンドを設定済みなら、code .でも開けます。

フォルダを開き直してから作業する

cloneしたフォルダ自体を開くと、AIも制作ルールとスライドの場所を把握しやすくなります。ターミナルは一度閉じて「ターミナル → 新しいターミナル」で開き直してください。

git branch --show-current

mainと表示されることを確認します。公開サイト用のgh-pagesへ切り替える必要はありません。

ここまでの確認：VS Codeでquarto-htmlを開き、decks/nco-intro/memo.mdを表示できればOKです。

06uvをインストールするPythonと、ビルドに必要なライブラリを管理します。共通

このテンプレートのコマンドはuv runで実行します。uvが必要なPythonを取得できるため、先にPythonを個別にインストールする必要はありません。

Windows / PowerShell

VS Codeのターミナルで、次を実行します。

winget install --id=astral-sh.uv -e

wingetが使えないときは、uv公式ページのWindows用インストーラー手順を利用します。

macOS / ターミナル

curl -LsSf https://astral.sh/uv/install.sh | sh

Homebrewを利用している場合はbrew install uvでも導入できます。どちらか一方で構いません。

インストール後はVS Codeを開き直し、quarto-htmlフォルダで新しいターミナルを開きます。

uv --version

ここまでの確認：uv …とバージョン番号が表示されればOKです。

公式：uvのインストール · Pythonの自動導入

07サンプルをビルドして開く環境を準備し、HTMLとPDFを実際に生成します。確認

以降のコマンドはすべて、README.mdとpyproject.tomlがあるquarto-html直下のターミナルで実行します。

Windowsでは、先に次のトグルを開いてUTF-8を設定してください。

Windows：最初にUTF-8を設定する

PowerShellで次を実行してから、この項目のコマンドを進めます。日本語を含むファイルをUTF-8で読み書きするための設定です。新しいターミナルを開いたら再度実行します。

$env:PYTHONUTF8 = "1"

1. Pythonとライブラリをそろえる

uv sync

プロジェクトにはPython 3.13が指定されています。必要なPythonとライブラリが取得され、.venvフォルダが作られます。初回はインターネット接続が必要です。

2. PDF生成用のブラウザを入れる

uv run playwright install chromium

Playwright用のChromiumをダウンロードします。普段使うChromeとは別に管理される、PDF出力とブラウザ検査用のブラウザです。

3. サンプルを生成する

uv run scripts/slides.py build nco-intro

QMDの変換、HTMLへの図の内包、ブラウザ検査、PDFの出力まで実行します。エラーが出た場合は、このページ下部の「困ったとき」を確認してください。

4. 出力したファイルを開く

  • output/nco-intro.html：エクスプローラー／Finderからブラウザで開きます。VS Code内で開いてコードが表示された場合も、ファイルの異常ではありません。
  • output/nco-intro.pdf：PDFビューアーで開きます。図は各ページの最後のstepで固定されます。

スライドは↑↓でページ移動、←→でstep移動。OまたはEscで一覧を開けます。

ここまでの確認：コマンドが正常終了し、HTMLの矢印操作とPDFの表示を確認できれば、制作環境の準備は完了です。

08自分のスライドを作り始めるメモを書いて、AIに最初の依頼をします。制作

1. 新しい発表のフォルダを作る

uv run scripts/slides.py new my-talk

my-talkは発表を区別する名前です。既存のサンプルをもとにしたい場合は、上のコマンドの代わりに次を実行します。

uv run scripts/slides.py new my-talk --from nco-intro

2. メモを埋める

decks/my-talk/memo.mdを開き、次の内容を書きます。図のプロンプト例は紹介ページの制作例も参考にしてください。

  • 対象読者と、一番伝えたいこと
  • スライドの説明順と、載せるデータ・文献
  • 図の配置、最初の状態、stepごとの変化、最後の状態

3. AIのチャットに依頼する

CodexでもClaude Codeでも、制作ルールと対象ファイルを指定して依頼します。Claude Codeにも同じルールを読ませるため、最初の依頼に明記しています。

まず AGENTS.md と .agents/skills/quarto-slides/SKILL.md を読んでください。
decks/my-talk/memo.md の案に沿って、スライドを作ってください。
対象読者と結論、図のstepを確認し、不足があれば質問してください。
編集後は uv run scripts/slides.py build my-talk を実行して、
HTMLとPDFを確認してください。

4. 生成物を見て修正する

output/my-talk.htmlとoutput/my-talk.pdfを開きます。「研究背景の図を大きく」「配送経路の最後に倉庫へ戻して」など、ページと変えたいことを指定して追加で依頼します。

次に進む：メモ → AIに依頼 → HTML/PDFを確認 → 修正、を繰り返します。

TROUBLESHOOTING

困ったときは、ここから。

「git / quarto / uvが見つからない」と表示される

インストール直後は、開いていたターミナルに設定が反映されないことがあります。VS Codeを完全に終了し、起動し直して新しいターミナルで確認します。

git --version
quarto --version
uv --version

1つだけ失敗する場合は、その道具の導入手順へ戻ります。Quarto拡張だけを入れてもquartoコマンドは追加されません。本体のインストールも確認してください。

AI拡張が見つからない・サインインできない

VS Codeの拡張機能一覧で、発行元がOpenAI／Anthropicになっているか確認します。インストール済みなら、コマンドパレットのDeveloper: Reload Windowで再読み込みします。

認証はブラウザで完了してからVS Codeに戻ります。利用できるプランや組織の設定はサービスごとに異なるため、AI拡張の項目にある公式手順でアカウントの条件を確認してください。

clone先が既にある・どのフォルダを開くか分からない

destination path … already existsと出たら、同じ場所にquarto-htmlが存在します。すでにclone済みなら、そのフォルダを「ファイル → フォルダーを開く」で開いてください。

ファイル一覧の直下にREADME.md、pyproject.toml、decks、scriptsがあれば正しい場所です。

「pyproject.tomlがない」「scripts/slides.pyがない」と出る

ターミナルの作業場所が異なります。VS Codeでcloneしたquarto-html自体を開き直し、新しいターミナルを作ります。親フォルダから作業している場合はcd quarto-htmlで移動してください。

「Executable doesn't exist」など、ブラウザがないと言われる

PDF生成に必要なChromiumを取得します。ブラウザ更新後などにも再取得が必要になる場合があります。

uv run playwright install chromium

成功したらビルドをもう一度実行します。

Windowsで「UnicodeDecodeError」や文字コードのエラーが出る

PowerShellでUTF-8を設定し、同じターミナルでビルドを再実行します。

$env:PYTHONUTF8 = "1"
uv run scripts/slides.py build nco-intro
HTMLを開くとコードが表示される

VS CodeやGitHubのファイル画面はHTMLをソースとして表示します。生成したファイルをエクスプローラー／Finderで探し、右クリックの「プログラムから開く／このアプリケーションで開く」からブラウザを選んでください。

公開済みサンプルはこちらのスライドリンクからそのまま閲覧できます。

ビルドが図の重なり・はみ出し検査で失敗する

エラーを含むターミナル出力をAIに渡し、「どのページのどのstepか確認して修正して」と依頼します。検査画像は.build/<発表名>/に保存されます。本文を短くする、ページを分ける、図の配置を調整するなどして再ビルドします。

自分のGitHubに保存したい。研究室のリポジトリは変わる？

clone後の編集は手元に保存されます。研究室のリポジトリへpushしない限り、公開元には反映されません。

自分のGitHubで管理する場合はUse this templateが表示される場合はテンプレートから作成、またはForkで自分のリポジトリを作り、そのURLをcloneしてください。研究室版をclone済みなら、接続先を確認してから自分のリポジトリに変更します。
